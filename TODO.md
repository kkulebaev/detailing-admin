### 3.2. Карточка клиента с историей визитов и авто ✅ Выполнено
Клик по клиенту на `/clients` → все его записи, машины, суммарно потрачено, дата последнего визита.

- **Статус:** реализовано (в `main`). Диалог `ClientDetailDialog.vue` + роут `/clients/:id` + эндпоинт `GET /api/clients/{id}`.

## UX формы записи

### 5.1. Автоподстановка клиента и его авто по телефону ✅ Выполнено
При вводе телефона в форме записи подтягивать имя и список машин уже известного клиента.

- **Статус:** реализовано (в `main`). Frontend-only: composable `use-client-lookup` поверх `GET /api/clients?q=`; при совпадении перезаписывает имя и первую машину, остальные машины — чипами под «Марка и модель». Телефон — первое поле секции.
- **Ценность:** повторный клиент вводится заново; растут опечатки в имени/авто и дубли в данных.
- **Сложность:** S–M — в форме уже есть работа с телефоном; нужен lookup-запрос по нормализованному номеру.
- **Тех. заметки:** Postgres (`clients` uniq по phone, `clientCars`). `normalizePhone` уже дает E.164 для поиска. На запись в Sheets не влияет.

### 5.2. Экспорт записей/клиентов в CSV ✅ Выполнено
Кнопка «Экспорт» на `/bookings` и `/clients` с учетом текущих фильтров.

- **Статус:** реализовано (в `main`). Server-side `GET /api/bookings/export` и `/api/clients/export` → `text/csv` (UTF-8 BOM + `;` + CRLF, RFC-quoting, OWASP-санитизация инъекций); суммы только admin, clients admin-only; фронт — `downloadFile` (raw-fetch → blob) + кнопки. CSV — снимок зеркала (не Sheets).
- **Ценность:** данные из Postgres-зеркала нельзя выгрузить для бухгалтерии/анализа вне Sheets.
- **Сложность:** S — сериализация уже отфильтрованной выборки; фильтры на `/bookings` готовы.
- **Тех. заметки:** Postgres, только чтение. Помнить про кодировку кириллицы — UTF-8 BOM для корректного открытия в Excel.

## Зависимости

### 6.1. Обновить `postgres` до 4
Перевести драйвер с 3.4.9 на 4.x. Отложено: версия 4.0.0 вышла 29.10.2026, уязвимостей в 3.4.9 `pnpm audit` не показывает.

- **Ценность:** новый пул и планировщик запросов, исправления корректности (например, `COMMIT`, на который сервер ответил `ROLLBACK`, теперь отклоняется).
- **Сложность:** M — правок в коде, вероятно, мало, основная работа в проверке: v4 переписывает пул, соединения и протокол, а юнит-тесты мокают БД и поломку драйвера не поймают.
- **Тех. заметки:** типы параметров теперь определяет сервер (`infer: false`), что касается колонок `timestamp` и `date`. `drizzle-orm` подменяет парсеры через `client.options`, и нужно убедиться, что v4 их учитывает. Запасной вариант: `infer: true` возвращает поведение v3 для типов параметров.
- **План проверки:**
  1. Прогнать один и тот же сценарий через HTTP на v3 и v4 на временной БД и сравнить ответы API: даты, массив `master`, транзакция `reorder`, конфликты БД. Не вызывать `POST /api/bookings`: он пишет в настоящую таблицу.
  2. Проверить накат миграций на пустую БД.
  3. Проверить подключение к проду на Railway.
